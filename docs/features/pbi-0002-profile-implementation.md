# PBI-0002 首次资料与级别管理实现切片

Status: approved
日期: 2026-11-12
范围：PBI-0002 / FEAT-001；支持既有 PBI-0003 年龄规则及版本留痕，但不宣称完成注销/副本删除/正式协议验收。

## 交付范围

TASK-0006 实现 users 资料字段与 user_consents 迁移、本人资料接口、1–8级校验、上海自然日次日生效及账号快照接口。TASK-0007 实现 PC 优先的 /onboarding、/settings，登录后资料缺失则进入填写页。TASK-0008 核对真实服务、内容安全/正式文本与会话历史集成证据；未齐备不产生 G4 go。

## 规则与边界

- 昵称去首尾空白后1–24字，不接受控制字符；出生年月仅 YYYY-MM，范围1900-01至当前上海月份。级别用严格整数1–8，拒绝布尔和字符串混入。出生年月下限为防无效输入的实现约束，不推断精确生日。
- 出生年月+14年的生日月仍需监护同意，次月首日解除；前后端使用同一月粒度规则。规则版本 month-conservative-v1。
- 本人身份只从服务器会话取，写接口沿用同源保护；拒绝客户端传入owner_id/user_id，重复提交资料409；资料与同意记录在同一个PG事务内提交，失败不留半份资料。
- 协议目录通过环境变量显式配置，manifest登记固定文档类型、版本和按UTF-8/LF规范化计算的SHA-256；正文变化而未更新清单则拒绝。GET /api/legal/manifest 供前端展示当前版本正文。缺正文或版本过期时拒绝提交，不能记录不存在的协议同意。
- 本机仅允许显式的 test_only 清单和测试文本；同意留痕 test_only=true，页面明确是测试流程。生产拒绝 test_only 文本。真实内容安全 check_text 尚未接入，生产资料提交保持拒绝；本机测试可注入验证器，不能把字符格式检查当内容安全通过。
- 当前级别即时用于首次资料；设置页变更写 level_next 与 level_next_effective=上海次日。多次修改以最后一次为准，改回当前级别取消待生效变更。读取或创建新会话前惰性滚动；快照仅返回整数，历史会话应保存该整数，不回写历史记录。
- 本轮不提供修改出生年月/昵称、账号注销、正式法律文本或真实会话历史页面；它们继续由相关PBI及后续任务承接。

## 接口

GET /api/users/profile：本人资料、当前/待生效级别、按月监护要求、资料完整状态。
POST /api/users/onboarding：nickname、birth_month、level、agreement_versions、guardian_consent；缺项422逐字段，未登录401，不完整/版本过期/需监护同意分别明确拒绝。
PATCH /api/users/level：level；未完成资料409；返回当前级别、待生效级别和生效日期。
GET /api/legal/manifest：类型、标题、版本、正文、test_only、当前上海月份及规则版本。

## 验证和依赖

复用已跑通的登录、PG协议开发环境及测试基础。G3仅确认开发可执行；正式PG/Redis、check_text、正式协议、用户历史会话仍为验收待办。AC1/2由字段校验、本人权限、并发/事务与PC流程验证；AC3由上海跨日/取消/覆盖/冻结快照合同测试验证，真实历史会话集成待后续。移动只作同一页面的基础自适应，不做专项优化。
