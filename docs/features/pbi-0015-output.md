# PBI-0015 错因输出基础切片

TASK-0028；依据定稿B3与BR-DIA-1/2。现有三件套仅本地预览，真实识别/确认/诊断尚未接入，本轮不扩大会话架构或添加另一套诊断状态机。

- 固定类别键：algorithm / complexity / boundary / runtime / format / implementation，对应六类错因。候选数组1～2项，顺序即可能性排序，类别不得重复；不编造数值置信度。
- 每条候选含非空说明及1～5条结构化定位依据；每条依据含来源question/evaluation/code、原文引用quote及行号（仅code允许且必填）。
- 模型引用须来自调用方给定的文本上下文。题干/评测引用必须为连续原文子串；代码引用必须为给定行号范围内的连续子串，行号不得超过实际代码行数。重复依据拒绝。此检查只证明引用存在，不能证明错因判断正确。
- P0 inference固定static_analysis；每次展示完整“基于静态分析推断——平台暂无本题测试数据”。不允许通过输出字段声称动态重跑、隐藏该提示或承诺确定正确。
- 内部检查器默认关闭。结构与原文检查后，必须分别调用安全检查和语义依据检查，且都严格返回True才产生带checks的已检视图；回调缺失/拒绝/异常均拒绝，不合成通过。安全回调查看候选全部文本，语义检查得到完整候选与上下文。
- 输入上下文包含题干、评测文字、学生代码及裁剪标记，长度边界与三件套一致。它是内部检查参数，不代表数据库确认已完成，不承担认证/持久化/计次。后续发布编排必须从已确认快照读取上下文，并绑定会话revision；不能直接接受客户端传来的checks声明。
- PC结果卡只接收通过解析的视图：按序显示中性类别章、AI显式标识、说明、来源/行号及原文引用；使用AiContent渲染生成说明，用户引用通过React原文转义。自行裁剪持续提示上下文可能不足。
- 本轮只新增`/dev/diagnosis-result`明确标注协议占位的页面用于布局验证，生产notFound。新诊断页不自动跳转到样例，“开始引导修正”禁用；不制造真实答案、历史记录、成功响应或扣次。
- 验收只覆盖AC1/3的结构与呈现基础。AC2固定生成参数下≥20例重复一致性及真实盲评、AC4识别确认复用、AC5一次诊断1次额度、持久发布/本人读取均待后续切片。
