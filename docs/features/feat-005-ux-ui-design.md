## 1. 范围与非范围

范围内：

- C1 用量指示器：会话页常驻显示当日剩余次数，计次完成后刷新（FR-LMT-02）。
- C2 超限提示与引导：第 16 次 AI 请求被拒时的提示文案、非 AI 功能引导入口、输入区禁用态（BR-LMT-5）。
- 两组件在"历史会话内继续追问被拒"场景的复用契约（FR-TUT-08 注明追问占日限额）。

非范围（不发明无关界面）：

- 会话页整体布局、顶栏结构、消息流渲染：PBI-0007/0008 设计范畴，本文仅约定 C1 的挂载槽位契约。
- 历史会话列表页：仅作为 C2 引导的跳转目标引用，不做设计。
- 游客体验额度展示（BR-LMT-4 设备指纹口径、注册当日切换）：PBI-0012 范畴。
- 错因诊断（FEAT-003）等入口页本身：本文仅给出 C2 作为通用超限提示的复用契约，入口页设计归各自特性。

## 2. 用户流

F1 正常计次流：

```
进入会话页 → C1 拉取并显示"今日剩余 n 次"
→ 发起 AI 请求（讲题/阶梯解锁/追问/变式）
→ 限额服务受理放行、计 1 次 → C1 立即刷新为 n-1
```

F2 会话内超限边界流（BR-LMT-5 不中断进行中会话）：

```
剩余 1 次时发起请求 → 放行（计第 15 次）→ 当前轮流式响应完整交付
→ C1 显示 0 → 输入区禁用 → 再发起任何新 AI 请求 → 被拒
→ 消息流末尾插入 C2 内联提示（已生成内容可正常回看）
```

F3 超限引导流（P0 裁剪口径）：

```
C2 提示 → 点主按钮"回看历史会话" → 历史会话列表（按时间倒序）
→ 回看任意会话内容（不受限额影响）
→ 在历史会话内继续追问 → 仍被限额拒绝 → 同位置复用 C2 提示
```

F4 跨 0 点恢复流：

```
次日重新进入会话页，或页面从后台回到前台（visibilitychange）
→ C1 重新拉取 → 显示重置后的剩余次数 → 输入区解除禁用
```

## 3. 信息层级与挂载契约

额度信息是辅助层，不与讲解内容争视觉优先级：常态下低视觉权重，仅在紧张/耗尽态提升权重（见 4.2）。

C1 挂载契约（对 PBI-0007 会话页的要求）：

- 会话页顶栏区域须提供一个常驻槽位承载 C1，移动端与桌面端断点下均常驻可见、不随消息流滚动。
- C1 不遮挡内容、不参与讲解主视觉层级；具体在顶栏内的左右位置由会话页布局定稿时决定。

C2 复用契约（对所有 AI 请求入口的要求）：

- 任何 AI 请求入口收到限额拒绝响应时，统一复用 C2 的文案与结构，不另造提示样式。
- P0 落地位置：讲题会话页、历史会话回看页（追问被拒时）；错因诊断入口随 FEAT-003 落地时按本契约接入。

## 4. 组件 C1 用量指示器

### 4.1 内容与结构

- 文案：`今日剩余 {n} 次`，n 为动态值（剩余 = 限额值 - 当日已用）。
- 纯文本指示器，非按钮、无展开交互；不显示限额总值（如"15"），避免与"限额值可配置"口径冲突。

### 4.2 状态

| 状态 | 条件 | 呈现 |
|---|---|---|
| 加载中 | 进入页面拉取未完成 | 显示 `--`，不阻塞页面其余内容 |
| 正常 | n > 3 | 默认文本样式 |
| 紧张 | 1 ≤ n ≤ 3 | 强调色（对比度 ≥ 4.5:1）；文案不变，数字本身即信息，不单靠颜色区分 |
| 耗尽 | n = 0 | 维持显示 `今日剩余 0 次`，配合 C2 与输入区禁用态 |
| 获取失败 | 拉取接口失败 | 显示 `--`，整体变为可点按重试；重试中回到加载中 |

紧张阈值 3 为设计决策（PRD 未定义预警线）：15 次额度下剩余 3 次约等于"再完成一次完整 L1→L3 讲解"的量，足以支撑用户规划剩余使用；阈值实现为前端常量，调整不发版可走配置时再收编。

### 4.3 刷新时机

- 每次计次放行后立即刷新（对齐"计次时点 = 受理放行即计"：放行后模型失败不退次数，因此放行即刷新不会出现"扣了又涨回"的回退态）。
- 进入会话页时拉取一次。
- 页面从后台回到前台（visibilitychange）时重新拉取，覆盖跨 0 点挂页场景。

## 5. 组件 C2 超限提示与引导

### 5.1 形态决策

采用消息流内联系统消息 + 输入区禁用，不用模态对话框。理由：

- BR-LMT-5 要求不中断进行中会话，且拒绝发生在用户已在会话上下文中时，模态的打断感与"用完即止"的语义不匹配；内联消息与会话上下文同处一个阅读流，回看时提示仍保留在时间线中，可解释"为什么后面没有新内容"。
- 实现上会话页为 CSR + SSE 消息流架构，拒绝事件天然可作为一条系统消息注入，无需新增全局弹层体系。

### 5.2 结构与文案

```
┌─────────────────────────────────────┐
│ 今日次数已用完，明天再来              │  ← 主文案（BR-LMT-5 原文）
│ 每天 0 点恢复，回看历史讲解不受限额影响 │  ← 副文案
│ [ 回看历史会话 ]                      │  ← 主按钮 → 历史会话列表
└─────────────────────────────────────┘
```

- 主按钮跳历史会话列表页（FR-TUT-08）；P0 仅此一个引导目标，错题本与重练入口随 P2（FEAT-008）上线后在本组件内补充。
- 不出现任何付费加次、购买入口（BR-LMT-5）。
- 本提示为系统消息，非 AI 生成内容，不挂 AI 生成标识（FR-OPS-04 标识对象为 AI 生成内容）。

### 5.3 输入区禁用态

- 耗尽后输入区禁用，占位文案：`今日次数已用完，明天再来`。
- 禁用而非"允许输入、提交再拒"：避免反复提交反复被拒的挫败循环；禁用不影响已生成内容回看与复制。
- 解除条件：C1 重新拉取到剩余次数 > 0（次日重置后）。

### 5.4 历史会话页复用

历史会话回看页内"继续追问"被拒时，在该会话消息流末尾插入同一 C2 结构；因用户已身处历史会话，主按钮替换为返回会话列表的等价入口或省略（实现时按该页导航结构取等价物，文案不变）。

## 6. 状态与边界覆盖汇总

| 场景 | 覆盖 |
|---|---|
| 加载中 | C1 显示 `--`，页面主体不阻塞 |
| 拉取失败 | C1 显示 `--`，点按重试 |
| 紧张预警 | n ≤ 3 强调色 |
| 会话内超限 | 当前轮完整交付 → C1 归零 → 输入区禁用 → 新请求插入 C2 |
| 历史会话追问超限 | 复用 C2 |
| 跨 0 点 | 重新进入或回到前台时拉取，自动恢复 |
| 空态 | 本组件无独立空态（剩余次数总有确定值或失败态） |

## 7. 无障碍

- C1 加 `aria-live="polite"`：次数变化自动播报且不抢焦点；紧张态不依赖颜色单通道传达（数字与文案始终完整）。
- C2 内联消息加 `role="status"`；插入消息流后不移动焦点，用户当前阅读位置不被打断。
- 输入区禁用使用 `aria-disabled="true"` 并以 `aria-describedby` 关联 C2 文案，读屏用户可获得禁用原因。
- 强调色与文本对比度 ≥ 4.5:1（WCAG AA）。
- C2 主按钮触控目标 ≥ 44×44px（移动优先）。
