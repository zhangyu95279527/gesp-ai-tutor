## 1. 范围与非范围

范围内：

- 诊断发起页：题目、OJ 评测结果截图、学生代码三个上传区；缺项拦截；评测状态识别失败的补传/文字描述分支。
- 识别回显确认：复用 FEAT-002 echo-card，追加评测状态章；确认后进入诊断（计 1 次）。
- 错因定位卡：六类错因章、多候选排序、定位依据、「基于静态分析推断」置信标注、AI 角标。
- 引导式修正：阶梯机制复用（诊断语境级标签）、L3 修正要点（不含完整改后代码）。
- 解决状态回填：已解决/未解决标记、未解决继续追问、解决后变式题衔接。
- 首页分段入口：「讲题 / 诊断」切换（对 FEAT-002 空态首页的增量挂载点）。

非范围：

- 会话页骨架、消息流、输入区、阶梯横条本体：FEAT-002 已定稿，本文仅给诊断语境的级标签映射。
- P1「静态分析 + 动态重跑验证」升级形态：依赖自建评测机（PBI-0025），本期不设计。
- 错因诊断在历史列表的完整回看页：复用 FEAT-002 C2，本文仅定列表项差异（C5）。

## 2. 设计语言复用与新增

全量复用 FEAT-002 tokens 与组件。新增 4 个组件级定义：

| 组件 | 说明 |
|---|---|
| `.seg-tabs` 分段入口 | 首页输入区上方「AI 讲题 / 错因诊断」分段控件：纸凹底胶囊轨，选中段 paper-raised 浮起 + indigo 文字；移动端全宽，桌面端居中 320px |
| `.upload-tile` 三件套上传区 | 虚线边界 tile（与 unlock-card 同语源：未提供的内容不伪装成实体）；粘贴即传后转为实底附件预览态；三区共享同一组件，仅图标与文案不同 |
| `.verdict-chip` 评测状态章 | mono 字体小章：WA=赭石底、TLE=赭石底、RE=danger 底、AC/部分得分=竹绿/纸凹底；颜色辅助 + 文字直书，不单靠颜色 |
| `.cause-chip` 错因类别章 | 宋体章 + 级别色不用：六类错因统一用 `--ink` 墨色实底章（错因分类是中性事实，不占阶梯色/警示色）；次候选降级为描边章 + 「可能性较低」 |

动效约束不变：诊断中骨架 shimmer 与打点复用 FEAT-002 A5，不引入新动效。

## 3. 用户流

F1 三件套上传主流（PBI-0014，PC 主场）：

```
首页切到「错因诊断」→ 题目区 Ctrl+V 粘贴文本/截图 → 评测结果区 Ctrl+V 粘贴 OJ 截图
→ 代码区粘贴文本（≤5000 字）或上传文件 → 三者齐备，主按钮激活
→ 「开始诊断 · 消耗 1 次」→ 识别（题目 + 评测状态）
```

F2 评测状态识别失败分支（BR-DIA-3）：

```
评测截图无法识别状态 → 行内提示「没认出评测结果」→ 补传截图 / 改用文字描述（输入评测状态与得分）
→ 文字描述与截图等价，齐备后可提交
```

F3 回显确认与诊断流（PBI-0015）：

```
识别回显（题干/考点/级别 + 评测状态章，可纠正）→ 确认（计 1 次，C1 刷新）
→ 诊断中（骨架 + 打点）→ 错因定位卡（首选错因 + 次候选 + 定位依据 + 置信标注）
```

F4 引导修正流（PBI-0016）：

```
错因定位卡底「开始引导修正」→ 修正阶梯 L1 自查方向 → 手动解锁 L2 定位线索（计 1 次）
→ 手动解锁 L3 修正要点（计 1 次，要点说明，不含完整改后代码）
→ 学生回 OJ 验证 → 回填「已解决 / 未解决」（不计次）
→ 未解决：继续追问（计 1 次/次）；已解决：变式题入口（生成+判读合并计 1 次）
```

F5 超限与失败复用流：

```
诊断发起/解锁/追问/变式任一环节 C1 归 0 → 消息流末尾 C2 卡 + 输入区禁用（FEAT-005 契约原文）
识别失败/无效输入 → 复用 FEAT-002 A9/A4 系统消息口径，不计次
```

## 5. 页面详设（帧索引）

原型 13 帧，贯穿同一道「数字反转」（GESP C++ 三级 · 整数运算），学生代码漏处理负数边界，OJ 判 WA。C1 计数跨帧连续（12→7）。端别分布：桌面 10 帧（J2 主输入为 PC Ctrl+V，OJ 刷题主场在 PC，诊断发起是三素材场景、PC 为一等行为）；移动 3 帧（缺项拦截、历史列表、未登录入口差异）验证响应式同构。

## 6. 组件状态表

### 6.1 三件套上传区 `.upload-tile`

| 状态 | 呈现 |
|---|---|
| 空态 | 虚线边界 + 图标 + 主文案（粘贴引导）+ 次文案（文件上传/相册入口） |
| 粘贴即传中 | 局部 shimmer，不阻塞其他区 |
| 就绪 | 实底 paper-raised：附件 chip（题目）/ 缩略预览 + verdict-chip（评测）/ 语法高亮预览 + 字数（代码）；右上「移除」文字按钮 |
| 缺项拦截 | 描边 danger + 行内红字，提交按钮保持禁用 |
| 识别失败 | 赭石行内提示 + 双分支入口（补传/文字描述），不清空已贴内容 |

代码区上限 5000 字符（FR-DIA-01）：超出后完整保留输入，明确显示计数与错误，禁止提交；文件上传在客户端读取后同样校验，服务端拒绝超长输入，不截断后诊断。文案「代码超过 5000 字符，请保留相关片段后重试；原文已保留」。如用户自行裁剪，确认区展示「本次仅诊断所提交片段，可能缺少上下文」，由用户确认后分析，不把片段当完整程序。

### 6.2 错因定位卡 `.cause-card`

卡头固定左 cause-chip（首选错因，墨色实底）右 ai-badge；次候选为描边章 + 「可能性较低」，最多 2 个候选（BR-DIA-1 允许排序，UI 收敛为首选 + 次候选两级，避免选择瘫痪）。定位依据为编号列表，每条引用具体证据（代码行号 / 评测状态 / 题面数据范围）。置信标注仅在缺乏测试数据时渲染（BR-DIA-2，P0 阶段恒渲染），赭石虚线框（与 beyond-note 同族）。

### 6.3 修正阶梯级标签映射

| 讲题语境（FEAT-002） | 诊断语境（本文） | 内容边界 |
|---|---|---|
| L1 · 思路提示 | L1 · 自查方向 | 提问式引导自查（如「拿这组数据手算一遍」），不给定位 |
| L2 · 关键步骤 | L2 · 定位线索 | 指向具体代码区域/变量，不给改法 |
| L3 · 完整讲解 | L3 · 修正要点 | 修正要点说明 + 行号引用；**不含完整改后代码** |

解锁交互、消耗预告、留痕、截断口径全部复用 FEAT-002 §6.3 与 BR-LMT-2。

### 6.4 解决状态回填卡 `.resolve-card`

系统消息属性（不挂 AI 角标）。双按钮平级；选「已解决」转竹绿留痕章 + 触发变式入口；选「还没解决」转赭石留痕章 + 输入区聚焦引导追问（追问计次）。可改判：留痕章旁「改状态」文字按钮（解决率统计以最终态为准）。

## 7. 响应式

- 诊断发起页：<768px 三 tile 单列堆叠；≥768px 两栏（题目/评测左列等分，代码区右列通高，代码需要更大编辑面）。
- 诊断会话页：复用 FEAT-002 §7 全部断点行为（移动单列 / 桌面左栏历史 + 右栏会话，列宽 640px 居中）。
- seg-tabs、upload-tile 两断点同构，仅密度差异。

## 8. 无障碍

- verdict-chip / cause-chip / 解决状态均文字直书（「WA」「边界条件遗漏」「已解决」），不单靠颜色。
- upload-tile 粘贴区为真实可聚焦控件，`aria-label` 区分三区；缺项拦截后焦点移至缺项 tile。
- 「基于静态分析推断」置信标注文字完整，非图标缩写。
- 代码区为 textarea 语义，行高亮预览 `aria-hidden`（避免读屏重复）。
- 对比度沿用 FEAT-002 基线；可点目标 ≥40px。

## 11. 设计决策与交接事项（定稿前记录）

1. 六类错因中「算法选择错误 / 复杂度不足 TLE」两类的章面文案是否附英文缩写（如 TLE）：原型按中文直书 + verdict-chip 已有英文缩写承载，实现期不再新增。
2. 桌面发起页代码区是否带行号：原型按无行号呈现（学生代码来自 OJ 复制，行号引用以「第 n 行」文字表达）；若盲评反馈定位引用不清，再评估加行号。
3. 「改状态」入口是否进 P0：原型已给文字按钮（解决率以最终态为准）；若裁剪，状态一经提交不可改，留痕章旁不渲染该按钮。
