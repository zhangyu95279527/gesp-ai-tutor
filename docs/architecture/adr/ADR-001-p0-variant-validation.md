# ADR-001 — P0 变式题真实运行校验能力前置

## Status
draft

日期：2026-11-11。供 GB 人工评审；本文件不代表决策通过，当前架构基线不变。

## Context

- PBI-0010 已定 AC 要求变式题参考解在构造数据上真实运行通过才下发。
- GA 基线将 Judge0 部署安排在 P1，P0 尚无批准的代码执行能力。
- 双 LLM 交叉判断不满足“运行通过”；在 api 进程执行代码不符合隔离边界。
- PBI-0012 依赖完整变式体验，不能把此缺口视作与 P0 无关。

## Decision

提议：仅将 Judge0 的内部变式校验能力提前到 P0，继续复用既定判题组件；不提前交付模考、公开判题入口或 P1 题库。

GB go 前 PBI-0010 的 tech-design-ready/dependencies-confirmed 不满足；PBI-0012 的完整体验依赖亦未就绪。其他无此依赖的 PBI 可分别推进。

## Options considered

| 方案 | 评审意见 |
|---|---|
| Judge0 内部校验能力前置 | 提议采用；保留已定 AC，但需验证容量与隔离 |
| 双 LLM 替代执行 | 不采用；不满足现有 AC |
| 变式延后至 P1 | 不采用为默认；改变 P0 效果闭环，须另行产品决策 |

## Consequences

- 新增 P0 部署与运维工作；提前承接 A-Q1/A-Q2 中与校验相关部分。
- API 仅内网调用校验器；无公网入口。沙箱禁止外网，限制 CPU/内存/进程/输出与执行时间，文件系统无业务密钥与用户存储挂载。
- 所有构造用例编译/运行成功且输出匹配才返回 passed；编译失败、超时、容量不足或服务不可用均 fail-closed，不下发题目。
- 校验资源与交互请求分别设并发上限；不得使 web/api/内容安全被判题负载拖垮。
- 回退为关闭变式生成并明确提示暂不可用，不能静默切换 LLM 判断并标记已校验；若回退，完整体验验收不通过。
- GB 必备证据：隔离逃逸/断网/资源限额验证、恶意与超时程序、正常变式端到端、同机资源容量、依赖固定版本及故障回退演练。
- 批准后在同一 GB 变更中同步基线部署时序、受影响 PBI 引用和门记录；未批准前不将本草案当作有效实现输入。

## Affected components/repositories

- gesp-tutor-api：变式校验适配器、Judge0 部署配置及验证。
- gesp-tutor-web：校验不可用/失败提示，禁止展示未校验题。
- gesp-ai-tutor：FEAT-002 技术设计、PBI-0010/0012、架构基线及后续 GB 记录。
