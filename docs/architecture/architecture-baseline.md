# Architecture Baseline（架构基线）

Status: in-review <!-- 文档生命周期: draft | in-review | approved | living | superseded -->

> 本基线承接 G2 通过的 PRD（docs/product/prd/），定义 MVP 阶段稳定架构边界，供 GA 人工门评审。
> 需人工拍板项：① 模型选型（O3 移交 GA）与图片识别管线（OCR-first + 多模态升级）；② 云厂商中立原则与首期落地（阿里云）、技术栈、组件仓划分；③ 判题方案（Judge0 定制）；④ 可观测性栈（企业级四层 + Langfuse）；⑤ 成本测算结论（NFR-COST-02）；⑥ CI/CD 流水线形态；⑦ 开放架构问题清单。

## 关键架构决策与置信度

| 决策 | 结论 | 置信度 | 取舍记录 |
|---|---|---|---|
| 部署形态 | 单一可部署后端（FastAPI 单体）+ 单机 Docker Compose | 90 | 放弃微服务可拆分性，换交付速度；百级用户规模无拆分必要；以模块化单体 + 无状态 + 配置外置纪律保留微服务/K8s 演进路径（见"演进路径"节），当前不为演进付拆分成本 |
| 云厂商策略 | 云厂商中立为稳定约束：应用只依赖行业标准协议（PG 线协议 / Redis 协议 / S3 API / OCI 镜像 / OTel / SMTP 或 HTTPS）；首期落地阿里云（单地域） | 85 | 无缝切换是设计原则：换厂商 = 换接口实现 + 换配置，不改应用代码；厂商专有 API（内容安全、事务邮件）一律薄接口隔离（见"云厂商中立与可移植性"节）；首期选阿里云因合规链路成熟（ICP 备案、生成式 AI 登记配合）与全家桶同 region 内网互通，该选择不构成绑定 |
| 模型选型（O3 移交） | 智谱 GLM-5.3-Flash | 75 | 可用档中输出价最低（¥2.8/M）；质量未经本场景实证，由盲评验证（A-Q3） |
| 图片识别管线 | OCR-first + 多模态升级：截图先经自托管 OCR（PP-OCRv4 模型，RapidOCR/ONNX 运行时，CPU）转文本 + 置信度，GLM-5.3-Flash 文本结构化；含公式/图表、OCR 低置信、用户纠正重识别走 VL 直读原图 | 80 | PRD 已定"截图输入先 OCR"与回显确认机制（FR-TUT-02），本行是架构承接；屏幕截图印刷体是 OCR 最强场景，评测状态枚举（WA/TLE/RE）规则解析确定性高于 VL 直读；图片首轮转文本后多轮追问不再带图（NFR-COST-03 主要落实点）；OCR 命中率 70% 为假设值，待真实截图评测集验证（A-Q6）；代价是单机多一个常驻容器 |
| 后端技术栈 | Python + FastAPI | 80 | LLM SDK 生态、SSE 流式、评测编排友好；放弃 Node 全栈同构的便利 |
| 前端技术栈 | Next.js（React + TypeScript） | 75 | 落地页/分享页需要 SSR 保 SEO 与首屏（NFR-PERF-03）；引入 SSR 运维成本 |
| 判题方案（P1） | 基于 Judge0 定制（自托管开源判题引擎） | 80 | 不重复造轮子：Judge0 自带成熟 isolate 沙箱与判题语义，仅做语言集/编译参数/集成定制；代价是引入其自带 PG/Redis 的额外服务组；第三方托管判题 API 违反 NFR-CMP-04，排除 |
| 可观测性栈 | Prometheus + Grafana + Loki + Langfuse（自托管；Langfuse 的 PG 复用托管实例独立库，Redis/ClickHouse 随容器） | 75 | 企业级四层（指标/日志/追踪/告警）+ LLM 专项观测；Langfuse 三依赖走混合方案：托管 ClickHouse 起步价超过其余云资源月成本总和不自建，PG 复用托管实例白得备份，Redis 队列数据可重建随容器；代价是容器数量与存储增加，纳入单机容量评审（A-Q2） |
| 数据层 | 托管 PostgreSQL + 托管 Redis（首期：阿里云 RDS PG / Tair） | 85 | 托管费换备份与可用性，降低自运维风险（NFR-REL-01）；应用仅依赖 PG 线协议与 Redis 协议，换厂商即换 endpoint 配置 |
| CI/CD | GitHub Actions：PR 门禁 + 主干构建镜像；发布人工触发、部署主机 self-hosted runner 执行 | 70 | 单环境无金丝雀，换简单可控；self-hosted runner 换不放行 SSH 入站、规避境内访问 GitHub 出向网络波动；代价是主机多一个常驻进程 |

## 当前视界

- 时间窗：2026-10 至 2026-12-26（GESP 第 16 次认证），考后 2027-01 复盘前为本基线有效期。
- 覆盖范围：P0（邀请制内测，2026-11 中下旬）+ P1（真题限时模考，2026-12 上旬）。P2（错题本）仅作数据模型预留，不作架构承诺。
- 规模假设：注册 300 / 冲刺窗口日活 100；邀请制内测期未登录体验流量 ≤ 50 设备/日；公开运营情景（生成式 AI 登记完成后）按 200 设备/日预估。
- 稳定边界（本期不变）：
  - 单 Web App 形态（O1），不做小程序/App；
  - 自有代码单一可部署后端，不拆分微服务（judge0、可观测性栈为成熟开源组件服务组，不计入拆分）；
  - 云厂商中立、单地域部署（首期落地阿里云），用户数据境内存储（NFR-CMP-04）；同 region 云服务间走内网 endpoint；
  - AI 推理全部走境内模型 API，不自建推理集群。
- 演进路径：P1 以 judge0 服务组（自托管判题引擎）加入；P2 为既有数据上的查询与提醒功能，无新边界；公开运营（O9 登记完成后）不引入架构变化，仅放量；放量后的扩容与微服务/K8s 演进见"演进路径"节。

- questions：识别后的题目文本、考点、级别判定、来源
- variant_attempts：变式题、首次作答、对错——金标准（变式题首次做对率）数据源
- exam_papers / exam_questions / exam_runs / judge_submissions：P1 模考与判题（judge_submissions 记录 judge0 submission token、评测状态与资源消耗映射）

- quota_usage：日限额流水（BR-LMT 口径）
- events：埋点事件，日报与漏斗数据源（FR-OPS-01）
- blind_eval_samples / blind_eval_scores：盲评抽样与评分（BR-EVA）

Redis 键：email_code:{email}（5 分钟）、quota:user:{uid}:{date}、quota:guest:{fingerprint}:{date}。

对象存储：uploads/（用户截图，仅本人会话可见，NFR-SAFE-03）、cards/（分享卡片，公开读）。

## 集成

### 模型选型决议（O3 移交 GA，本次评审核心项）

**决议建议：智谱 GLM-5.3-Flash 为唯一接入模型。置信度 75。**

约束：NFR-CMP-04 要求不使用境外模型 API 处理用户数据，候选限定为境内服务商；图片识别不全量依赖多模态——截图主通道为自托管 OCR（见"图片识别管线"节），模型仍需具备多模态能力承担 VL 升级通道。

候选对比（2026-10 公开刊例价）：

| 模型 | 输入 ¥/M tokens | 输出 ¥/M tokens | 多模态 | 判断 |
|---|---|---|---|---|
| 智谱 GLM-5.3-Flash | 0.8（缓存命中 0.23） | 2.8 | 原生（图/文/文件） | 选用：输出价最低，编码能力强，成本测算见下文 |
| 豆包 doubao-seed-1.6-vision（火山引擎） | 0.8（≤32K，缓存 0.16） | 8.0 | 是 | 备选 |
| 通义 qwen3-vl-plus（阿里百炼） | 1.0（≤32K） | 10.0 | 是 | 备选 |

切换机制：LLM 网关以配置指定模型与密钥；盲评（BR-EVA）不达标或价格政策变化时，切换备选模型只改配置与 prompt 模板，不改调用方代码。

### 图片识别管线（OCR-first + 多模态升级）

承接 PRD：J1/J2 已定"截图输入先 OCR"、FR-TUT-02 回显确认（同会话 1 次免费重识别）、NFR-COST-03 会话上下文复用。输入全为屏幕截图（不做相机直拍、排除纸质拍照），印刷体高分辨率是 OCR 最强场景。

```
截图上传 → 前端压缩/服务端校验（NFR-PERF-02）
        → ocr 服务（自托管，PP-OCRv4 模型 / RapidOCR ONNX 运行时，CPU）→ 文本 + 置信度
        → 路由判定：
          ├ 置信度达标且无公式/图表特征 → GLM-5.3-Flash 文本结构化（题面 / 考点 / 级别）
          │   评测结果截图（FR-DIA-01）：OCR + 规则解析评测状态枚举（WA/TLE/RE/部分得分）与测试点表格
          └ 低置信 / 含公式图表 / 结构化校验失败 / 用户纠正后重识别 → GLM-5.3-Flash 多模态直读原图（VL 升级通道）
        → 回显确认（FR-TUT-02）；识别结果以文本进入会话上下文，后续追问轮次不再带图（NFR-COST-03 的主要落实点）
```

要点：

- 不走全多模态的理由：评测状态枚举解析要求确定性（VL 有幻觉风险）；文本可进 LLM 上下文缓存（¥0.23/M）而图片 token 不可缓存、多轮重复带图浪费；OCR 本地 ~1s + 文本首 token 快于 VL 大图 prefill（NFR-PERF-01）。
- 不走全 OCR 的理由：含公式/图表/复杂排版的题（PRD 明确此类用截图保真）OCR 啃不动；用户纠正后的重识别需要 VL 直读原图。VL 通道由 GLM-5.3-Flash 原生多模态承担，零额外接入。
- ocr 服务无状态、无自有数据表，api 经内网 HTTP 调用；单并发队列 + 容器内存上限 ≤ 1G，容量并入单机评审（A-Q2）。
- OCR 命中率 70% 为假设值，P0 开发期以真实 OJ 题面/评测截图建评测集回归验证（A-Q6）；命中率显著偏低时上调 VL 路由阈值，管线结构不变。

## 身份/安全

- 认证：邮箱验证码无密码登录（FR-ACC-01），登录态 30 天；验证码 5 分钟有效、重发间隔 60 秒、连续错误 5 次锁定 10 分钟。
- 门控：邀请码注册（FR-ACC-08，O9 内测期）；登记完成后配置化整体关闭。
- 访客识别：设备指纹 + 浏览器标识（FR-ACC-06），仅用于体验额度计数。
- 未成年人：14 周岁分层 + 监护人同意勾选留痕（FR-ACC-03、BR-CMP）；数据最小化见"数据"节。
- 传输与秘密管理：全站 HTTPS；无用户密码体系；模型/邮件等密钥经环境变量注入，不入仓。
- 内容安全：双向过滤 + 拦截日志 + 邮件申诉入口（FR-OPS-03）。
- 合规前置：ICP 备案（NFR-CMP-05）在域名上线前完成；生成式 AI 登记（NFR-CMP-01）为公开上线前置（O9），邀请制内测期不面向公众。

## 运行时/部署

拓扑（云厂商中立、单地域；括注为首期阿里云落地）：

```
用户浏览器 ─→ CDN / 对象存储（静态资源、分享卡片图；首期：阿里云 CDN / OSS）
          ─→ web 容器（Next.js，单云主机；首期：阿里云 ECS）
          ─→ api 容器（FastAPI，单云主机）─→ 托管 PostgreSQL（首期：阿里云 RDS；含 Langfuse 独立库）
                                        ─→ 托管 Redis（首期：阿里云 Tair）
                                        ─→ 对象存储私有桶（S3 API；首期：阿里云 OSS）
                                        ─→ 智谱 LLM API（出公网）/ 内容安全薄接口 / 邮件薄接口（同 region 内网 endpoint）
          ─→ ocr 容器（PP-OCRv4 / RapidOCR，CPU，api 经内网 HTTP 调用）
          ─→ judge0 服务组（P1）：server + worker + 自带 PG/Redis，api 经内网 HTTP 调用
          ─→ 可观测性服务组：Prometheus + Grafana + Loki + Langfuse（web/worker + 自带 Redis/ClickHouse 容器）
```

- 形态：单台云主机 + Docker Compose 起步（web / api / ocr / judge0 / 可观测性栈 + nginx 反向代理；首期：阿里云 ECS）；业务 PostgreSQL 与 Redis 使用托管实例（首期：阿里云 RDS / Tair），备份与基础可用性由云厂商承担；Langfuse 的 PG 复用托管实例独立库（独立账号，prompt 版本与评分元数据随 RDS 备份），Langfuse 的 Redis（队列）与 ClickHouse（trace 分析数据，设保留期）及 judge0 自带存储随容器卷部署（队列与分析/判题数据可重建，不纳入备份关键路径）；云主机系统盘与数据盘开启自动快照。
- judge0 定制项：仅启用 C/C++ 语言集；编译参数对齐 GESP 官方评测环境（g++、-O2、-std=c++14，以当年官方公布环境为准）；沙箱断外网；按题批量提交测试点；worker 并发与超时/内存参数按 NFR-PERF-04（≤ 30s）调优（A-Q1）。
- CI/CD：见"交付流水线"节。
- 可用性（NFR-REL-01，冲刺窗口 ≥ 99.5%）：当前规模下单机 + 托管数据库可达；冲刺窗口前完成一次恢复演练（镜像重建 + 数据恢复），是否加双副本在 P1 上线评审复核（A-Q2）。
- 合规部署项：域名经云接入商（首期阿里云）备案系统完成 ICP 备案；生成式 AI 登记完成前站点仅邀请制访问，落地页不公开投放。

### 云厂商中立与可移植性

原则：云厂商中立是稳定约束，首期落地阿里云不构成绑定；无缝切换 = 换接口实现 + 换配置，应用代码零改动。

应用只依赖行业标准协议：

| 能力 | 依赖的标准协议/形态 | 首期落地（阿里云） | 切换动作 |
|---|---|---|---|
| 关系数据库 | PostgreSQL 线协议 | RDS PG | 换 endpoint 配置；pg_dump / 逻辑复制迁移存量 |
| 缓存/计数 | Redis 协议 | Tair | 换 endpoint 配置；计数与验证码数据可重建，无需迁移 |
| 对象存储 | S3 API（私有桶 + 签名 URL） | OSS | 换 SDK endpoint 与凭据配置；存量对象脚本搬迁 |
| 容器交付 | OCI 镜像 | ACR | 换 registry 地址；镜像 tag 与内容不变 |
| 可观测性 | Prometheus / Loki / OTel / Langfuse（自托管） | 随容器部署；Langfuse 的 PG 走标准 PG 线协议（复用托管实例独立库） | 容器部分无切换面；Langfuse 的 PG 切换动作同"关系数据库"行 |
| CDN / HTTPS | 标准 CDN 行为 + 证书 | 阿里云 CDN | 换 CNAME 与证书 |

厂商专有 API 一律薄接口隔离（应用侧只见接口，不见厂商 SDK）：

- 内容安全：check_text / check_image 接口；首期实现阿里云内容安全。切换 = 新增一个接口实现类 + 配置。
- 事务邮件：send_mail 接口（或 SMTP）；首期实现阿里云 DirectMail。切换 = 新增一个接口实现类 + 配置。

不使用的绑定源（纪律）：云厂商专有数据库特性（存储过程、厂商私有扩展）、专有消息队列、云函数、厂商 IAM 内嵌鉴权——应用侧一律不使用，避免隐性绑定。

切换成本预期：真实切换时工作量集中在存量数据搬迁、DNS 与 ICP 备案接入变更（境内合规动作，与应用无关）；应用侧改动预期为零。

## 演进路径（微服务/K8s 预留）

原则：当前不建微服务与 K8s（决策表"部署形态"不变），但守住下列纪律，使未来演进为"编排与部署改造"而非"应用重写"。进入阶段 3/4 均须走架构演进评审（ADR）并更新本基线。

现在必须守住的工程纪律：

- 模块化单体：api 内部模块（acc / tut / dia / exa / wbk / shr / lmt / ops）即未来服务边界；模块拥有各自数据表，跨模块只走进程内接口，不跨模块联表——未来拆服务即按模块切分代码与表所有权。
- 无状态容器：web / api 进程内不保存会话与业务状态（状态全在 PostgreSQL / Redis / 对象存储），水平扩展零应用改造。
- 配置外置：全部配置与密钥经环境变量注入（已成立），K8s 演进平移为 ConfigMap / Secret。
- 健康端点：api /health 已在 CI 冒烟使用，未来直接对接 K8s 就绪/存活探针。
- 镜像即交付：不可变 tag 已成立，上 K8s 仅替换编排层。
- 云厂商中立：全部云依赖走行业标准协议、厂商专有 API 薄接口隔离（见"云厂商中立与可移植性"节）；观测体系（Prometheus / Loki / Langfuse + OTel）不绑定任何云，trace_id 经 OTel 标准 header 天然跨进程传播，拆服务后观测体系无需重建。

分阶段演进与量化触发：

| 阶段 | 形态 | 触发条件 | 改造性质 |
|---|---|---|---|
| 1（当前） | 单云主机 + Compose（首期：ECS） | — | — |
| 2 垂直扩容 | 云主机 / PG / Redis 升配（首期：ECS / RDS / Tair） | 单机 CPU / 内存持续 > 60%，或数据库连接数逼近上限 | 纯运维，无应用改造 |
| 3 水平扩展 | 多云主机 + 负载均衡 + web/api 多副本（首期：ECS + SLB） | 日活 > 2000，或升配不经济，或可用性目标上调 | 部署改造：SSE 多副本经负载均衡会话亲和或 Redis pub/sub 扇出（届时 Feature 技术设计定稿）；应用无状态不改造 |
| 4 K8s + 微服务 | K8s 托管集群（首期：阿里云 ACK）+ 按模块拆服务 | 团队并行发布冲突频发、单模块资源热点、流量再上一个量级 | 编排与数据拆分：compose → K8s；judge0 / Prometheus / Loki / Grafana / Langfuse 均有官方或社区 Helm Chart；模块边界与表所有权已由纪律 1 就位 |

记录在案的将来工作（现在不建）：

- SSE 多副本扇出（阶段 3 定稿）。
- 拆服务后的模块间内网 RPC（阶段 4 引入，现在保持进程内调用）。
- 阶段 4 的数据拆分与分布式事务方案（届时按模块边界逐域评审）。

## 交付流水线（CI/CD）

原则：主干开发 + 短生命周期分支；CI 结果即合并门禁；镜像不可变 tag；发布动作人为触发（对齐 G5 发布门）；冲刺窗口发布冻结。环境仅生产一套 + 本地 docker compose 全栈联调（兼作恢复演练环境），不建独立 staging。

CI（GitHub Actions，按仓）：

| 仓 | PR → main（合并门禁） | push main |
|---|---|---|
| gesp-tutor-api | ruff、mypy、pytest 单测 | + 构建镜像推 OCI 镜像仓（tag = git sha；首期：阿里云 ACR） |
| gesp-tutor-web | eslint、tsc、单测、next build | + 构建镜像推 OCI 镜像仓（tag = git sha；首期：阿里云 ACR） |
| gesp-ai-tutor（交付仓） | 人工评审即门决策（G1/G2/G5/GA/GB） | status.md 由 scripts/build-status.py 重生成随提交 |

CD：

- 发布：workflow_dispatch 选择镜像 tag 人为触发；部署主机以 self-hosted runner 执行 `docker compose pull && up -d`，不放行 SSH 入站。
- 迁移：部署流程内执行 Alembic 前向迁移（upgrade head），与镜像同版本发布。
- 冒烟：部署后自动检查 web 200、api /health、judge0 /about、Langfuse 健康端点；失败按 P1 告警（联动可观测性节）。
- 回退：compose 回指上一镜像 tag，按需执行迁移回退脚本；回退路径纳入冲刺窗口前恢复演练（A-Q2）。
- 冻结：冲刺窗口（NFR-REL-01 定义的考前窗口）发布冻结，仅 hotfix-v* 分支修复，修后回合并 main。

构建与依赖纪律：

- 镜像 tag 不可变：主干构建用 git sha；发布 tag v* 时为同内容镜像重打 semver tag；compose 固定 tag，不用 latest。
- judge0、Prometheus、Grafana、Loki、Langfuse 一律使用官方镜像 pin 版本，不自建其构建流水线。
- 境内构建加速：pip / npm 使用境内镜像源，基础镜像经镜像加速器拉取（首期：ACR 镜像加速器）。
- 秘密：CI 凭据（镜像仓、部署配置）存 GitHub Secrets；运行时密钥注入方式不变（见"身份/安全"节）。

追溯与门禁：

- 组件仓创建时在 GitHub 开启 main 保护（必需 CI 状态检查通过方可合并），登记 .agent/local/git-policy.yaml。
- 任务分支 PR 附 G4 验证证据（CI 结果 + 验收标准核对），合并以 TASK-xxxx anchor 追溯。

## 可观测性

按企业级四层建设：指标 / 日志 / 追踪 / 告警，叠加 LLM 专项观测与质量评估闭环。工具栈：Prometheus + Grafana（指标、看板、告警）、Loki（日志）、OpenTelemetry（埋点与追踪）、Langfuse 自托管（LLM trace、prompt 版本、成本、人工评分）。业务埋点入 events 表不变，支撑指标日报（NFR-REL-02）。

### 指标体系

业务指标（日报，NFR-REL-02）：活跃用户、会话数、变式题首次做对率、限额触顶率、触顶用户次日留存率、体验转化漏斗（落地页→体验发起→体验完成→注册）、分享回流。

系统指标：
- api / web（RED）：请求速率、错误率、延迟分位（按路由）；SSE 连接数与断连率
- 前端 RUM：Web Vitals（LCP / CLS 等），验证 NFR-PERF-03 首屏 P75 ≤ 3s
- 主机与容器：CPU / 内存 / 磁盘 / 网络、容器存活
- PostgreSQL / Redis：连接数、慢查询、缓存命中率、内存占用
- judge0（P1）：队列深度、单题判题耗时、评测状态分布（AC / WA / TLE / RE / CE）

LLM 指标（按模型 × 功能模块（tut / dia / variant / exa_review）× 级别段（1–4 / 5–8）切分）：
- 用量：输入 / 输出 token、上下文缓存命中率、请求数
- 成本：单次成本、日 / 月累计成本，对照 NFR-COST-02 测算基线，偏差 > 30% 触发复核
- 性能：首 token 延迟（TTFT）P50 / P75 / P95，对照 NFR-PERF-01 ≤ 5s；完整生成时长、吞吐 tokens/s
- 可靠性：流式中断率、重试率、限流（429）次数、超时率、空响应与格式校验失败率（变式题结构化输出）
- 安全：输入 / 输出内容安全拦截率与类别分布

质量指标（效果闭环）：
- 金标准：变式题首次做对率、教练盲评均分（BR-EVA）
- 过程：阶梯解锁深度分布、追问轮次、"听懂了"标记率
- 变式题难度校准：盲评"偏易"占比 > 20% 触发 prompt 回炉（BR-VAR-2）

### 日志

- 全组件结构化 JSON 日志汇入 Loki；统一 trace_id 贯穿 web → api → 会话状态机 → LLM 网关 → 模型 API
- LLM 请求 / 响应全量留痕（Langfuse trace）：prompt 模板版本、输入、输出、token、耗时——用于盲评回溯、质量问题定位与 prompt 迭代对比
- 脱敏纪律：日志不落邮箱等个人信息；用户截图不进日志，仅留对象存储引用 ID
- 内容安全拦截单独日志流，保留申诉核查所需上下文（FR-OPS-03）

### 追踪

- OpenTelemetry：每个 AI 请求一棵调用树（识别回显 → 阶梯生成 → 安全过滤 → 变式），span 属性带模型、prompt 模板版本、token、TTFT
- 慢调用定位到环节（识别 / 生成 / 过滤 / 判题），支撑 NFR-PERF-01 / 04 的持续验证

### 告警（分级）

| 级别 | 条件（示例阈值） | 响应 |
|---|---|---|
| P1 立即 | api 不可用；LLM 错误率 > 20% 持续 5 分钟；内容安全服务不可用 | 邮件 + webhook，立即处理 |
| P2 当日 | TTFT P75 > 5s 持续 30 分钟；日成本超预算阈值；judge0 队列积压 > 10 分钟；磁盘 > 80% | 当日处理 |
| P3 周期 | 盲评均分 < 3.5；变式"偏易"占比 > 20%；触顶用户次日留存显著低于整体 | 进入迭代复盘 |

### LLM 专项与评估闭环（Langfuse）

- prompt 模板版本管理：变更自动关联产出 trace，每次重大迭代后按 BR-EVA 抽样 30 个会话
- 盲评工作流：抽样会话进入 Langfuse 标注队列，2 名教练独立打分、分差仲裁；结果回写 blind_eval_scores 并出日报；NFR-REL-03 每日 10 会话人工抽检走同一入口
- 成本核算：按 trace 聚合 token × 单价，产出月度成本报告与 NFR-COST-02 基线对照
- 数据保留：trace 与日志热存 30 天，归档保留至 2027-01 考后复盘（对齐 NFR-DATA-02）

## 重要约束/NFR

### 成本测算模型（NFR-COST-02）

输入假设：

- 内测期日请求量 = 100 活跃 × 8 次/日（均值假设，上限 15）+ 50 访客 × 1 次 = **850 次/日**；打满上界 = 100×15 + 50 = **1550 次/日**。
- 单次 token 估算：文本粘贴路径（占比 40%）输入 ~2.5K / 输出 ~1.5K；截图路径（占比 60%）经 OCR-first 管线（见"图片识别管线"节）：OCR 命中转文本（60%×70%）输入 ~2.5K，VL 升级直读（60%×30%）输入 ~4K（单张截图约 1.5K tokens）→ 均值 **输入 ~2.8K、输出 ~1.5K**。
- GLM-5.3-Flash 单价：输入 ¥0.8/M、输出 ¥2.8/M。

测算结果：

| 情景 | 单次平均成本 | 日成本 | 月成本 |
|---|---|---|---|
| 内测期（均值 850 次/日） | ≈ ¥0.0064 | ≈ ¥5.5 | ≈ ¥164 |
| 内测期（打满 1550 次/日） | ≈ ¥0.0064 | ≈ ¥10.0 | ≈ ¥300 |
| 公开运营（+200 访客/日，均值） | ≈ ¥0.0064 | ≈ ¥6.4 | ≈ ¥193 |
| 公开运营（打满） | ≈ ¥0.0064 | ≈ ¥10.9 | ≈ ¥328 |

说明：截图路径已按 OCR-first 管线拆分（OCR 命中率 70% 为假设值，A-Q6 验证；命中率偏差通过 VL 路由阈值吸收，均值在 ¥0.0062–0.0067 区间波动，不改结论量级）；追问轮次图片转文本后的上下文复用与缓存命中（¥0.23/M）未计入，属保守上界。P1 模考判分为非 AI 推理（BR-LMT-3），不增加 token 成本；ocr 服务自托管无推理 API 费用，主机资源并入云资源附注与 A-Q2 容量评审。

结论：**月度推理成本量级 ¥160–330，对预算不构成约束；O3 的 15 次/日限额在成本维度成立，无需回审。** 成本关注点转移至公开运营后的访客流量规模，届时按 LLM 计量月报复核。

云资源成本附注（量级估算，置信度 60，采购前按刊例复核）：标准资源口径——4C8G 云主机 + 托管 PG 基础版 2C4G + 托管 Redis 1G + 对象存储 / CDN 按量 + OCI 镜像仓 + 事务邮件按量；按首期阿里云刊例（ECS + RDS PG 基础版 + Tair + OSS / CDN + ACR 个人版（免费）+ DirectMail），月度量级 ¥500–800；阶段 2 升配前为产品主要固定成本。Langfuse 三依赖不为自购托管付费：PG 复用托管实例独立库（边际 ¥0），Redis 与 ClickHouse 随容器（边际 ¥0；托管 ClickHouse 单副本最小规格约 ¥400–800/月，超过上述其余云资源总和，当前规模不自建；全托管三件套合计约 ¥500–1200/月，会使云资源月成本翻倍以上，排除）。代价是单机内存吃紧（ClickHouse ~2G），升配 8C16G 与否并入 A-Q2 容量评审，不归因于本决策。
