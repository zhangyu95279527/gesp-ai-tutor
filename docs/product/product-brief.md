# Product Brief（产品简报）

Status: in-review <!-- 文档生命周期: draft | in-review | approved | living | superseded -->

## 产品愿景

让每个备考 GESP C++ 的学生，都有一个懂考纲、懂级别、循循善诱的 AI 辅导老师。

- 中期图景：成为 GESP C++ 备考的默认工具，覆盖"讲题 — 模考 — 错题"备考闭环。
- 远期选项（不在本期承诺）：沿信奥链路延伸至 CSP-J/S；扩展 Python / 图形化语言线。

## 问题

GESP（CCF 编程能力等级认证）C++ 线是中小学生信奥升学路径的关键节点（级别结构与 CSP-J/S 衔接政策属公开信息，时效待确认）。备考学生在刷题训练中遇到三个相互叠加的问题：

1. **讲题不对口（假设 H1）**：遇阻时缺少即时、贴合所报级别与考纲的讲解。问老师受时间限制；家长普遍辅导不了 C++；通用大模型不对齐 GESP 级别与考点。
2. **判分后不知错哪（发起人明确陈述的痛点，待种子期验证）**：学生在洛谷等 OJ 平台刷题判分后（不得分或未满分），只知道"错了"，不知道错在哪——是算法选错、边界条件遗漏还是实现细节问题，缺少定位与引导。典型场景：刷题遇错 → 将题目与洛谷评测结果拍照/截图上传至本平台，并提交自己的代码 → 由平台诊断错因并引导修正。
3. **练习碎片化（假设 H4）**：缺少结构化的真题限时模拟与错题管理，练习不成体系，进步不可量化。

为什么是现在：大模型的代码理解与讲解能力已成熟到可支撑辅导场景（能力达标线本身需在种子期验证，见 H6）。

## 目标用户

- **首要用户（使用者）**：备考 GESP C++ 1–8 级的中小学生。
  - 1–4 级入门段：多为小学高年级至初中，自制力弱，最需要引导式讲解。
  - 5–8 级进阶段：衔接 CSP-J，动机最强、刷题量最大，对错因定位需求最迫切。
- **相关方**：家长（关注进步可视化，未来的潜在付费方）；信息学老师（潜在的背书与传播节点）。
- **首阶段非目标用户**：图形化 / Python 语言线考生；成人编程学习者；学校 / 机构采购场景。

## 价值主张

刷题遇阻时，不只告诉学生"对不对"，更让学生知道"错在哪、该怎么想"。

三条核心价值（对应三个产品模块，P0 为最高优先级）：

1. **P0 引导式 AI 答疑 / 讲题**：提供解题思路和方法，引导学生自己思考，不直接给出答案；按学生所报级别控制讲解深度。采用阶梯式引导（思路提示 → 关键步骤 → 完整讲解，卡死可逐级解锁，解锁行为留痕）；讲解后推送同考点变式题，检验是否真懂。
2. **P0 错因诊断**：学生在洛谷等 OJ 平台刷题遇错后，拍照/截图上传题目与评测结果并提交自己的代码，平台定位具体错误类型（算法选择 / 复杂度不足（TLE）/ 边界条件 / 运行错误（RE）/ 格式问题 / 实现细节）并以引导式讲解帮助其自行修正。与 OJ 平台是互补关系而非替代关系——刷题主场仍在 OJ，本平台是其之上的"诊断 + 引导"层。
3. **P1/P2 真题模拟 + 错题本**：历届真题限时模考并即时讲评；错题自动归集、支持重练。

与现有替代方案的差异：

| 替代方案 | 不足 |
|---|---|
| 培训机构课程 | 贵、时间不灵活、非个性化 |
| 通用大模型 | 不对齐 GESP 考纲与级别；倾向直给答案，不利于学习 |
| OJ 刷题平台（洛谷等） | 非竞品，是互补的刷题主场：有题有判分，但无讲解、不定位错因，正是本平台的切入缝隙 |
| 教辅书 / 真题集 | 无互动、无反馈、不可量化 |

商业模式：**免费工具先行**，首阶段不做任何付费设计；变现后置（候选方向：家长端引导过程报告、高级功能订阅、内容增值、机构合作，待效果验证后在后续门点决策）。

## 证据 / 假设

### 已确认事实（项目上下文与本次 Discovery 决策）

- 产品定位：面向 GESP 备考学生的 AI 编程辅导互联网产品，免费工具先行。
- 覆盖范围：C++ 1–8 级。
- 产品形态：AI 答疑 / 讲题 + 真题模拟 + 错题本三模块，AI 讲题为第一优先级。
- 讲解原则：引导式，不直接给答案（发起人明确决策）。
- 首个里程碑：锚定 2026 年 12 月考期，以公域内容获客招募种子用户，验证学习效果。

### 领域背景（公开信息，时效性待确认，不作为已验证证据）

- GESP 由 CCF 主办，分 1–8 级，含图形化 / Python / C++ 三条语言线，统考通常每年 3 / 6 / 9 / 12 月举行；12 月考期具体日期与报名截止以 CCF 官方通知为准。
- GESP C++ 高级别历史上与 CSP-J/S 存在衔接政策（免第一轮认证），是备考群体的核心动机之一。
- 洛谷等 OJ 平台提供判分但不提供讲解，判分反馈（不得分 / 部分得分）不指出具体错误原因。

### 假设（待验证，非证据）

- H1：学生对"即时、贴合级别考纲的讲解"存在刚性需求。
- H2：家长对"针对性强、可量化进步"的备考工具有付费意愿（本期不验证，变现后置）。
- H4：学生缺少结构化真题模拟与错题管理，练习碎片化。
- H6：AI 引导式讲解质量能达到学生可用标准（比直给答案更难，需建立评测集验证）。
- H7：公域内容获客能在约 7 周内获取足量种子用户（高风险假设，见风险 R1）。
- H8：学生在洛谷等 OJ 平台刷题遇到无法自行诊断的错误时，愿意把题目（拍照/截图）与自己的代码上传到本平台，换取错因诊断与引导——即"互补工具"场景成立，不要求用户从 OJ 平台迁移。

## 初始边界

MVP 范围（锚定 2026 年 12 月考期，按优先级分批上线）：

- P0：引导式 AI 答疑 / 讲题 + 错因诊断（先上线）。输入形态：题目与评测结果拍照/截图 + 学生代码（粘贴或文件上传）；拍照讲题不依赖自有题库。P0 初期以"静态代码分析 + 评测结果截图"为诊断依据；自建评测机与测试数据随 P1 建设，建成后诊断升级为"静态分析 + 动态重跑验证"。题库建设压力主要集中在 P1 真题模拟模块。
- P1：真题模拟（限时 + 判分 + 讲解入口）。
- P2：错题本（最简实现：自动归集 + 重练入口；交付紧张时可降级）。
- 题库：C++ 1–8 级历届真题，按级别分批入库；首批级别段在 PRD 阶段依据公开报考规模信息确定。
- 获客配套：公域内容引流所需的最小分享能力（如讲解页分享卡片）。

明确不做（首阶段）：

- 图形化 / Python 语言线；体系化课程；教师端 / 机构端功能；付费功能；社区 / 社交；原生 App（终端形态见开放问题 O1）。

## 成功信号

里程碑锚点：G1 评审 → PRD（G2）→ MVP 分批上线（P0 目标 11 月中下旬可用）→ 12 月考期冲刺使用 → 考后效果复盘。时间盒紧张，属激进目标。

以下量化值为建议目标，非承诺基线，在 G2 PRD 阶段依据基线数据校准：

- 种子规模：注册用户 ≥ 300，其中考前两周活跃（使用 ≥ 3 次）≥ 100。
- 参与度：模考完成率 ≥ 50%；讲题会话人均交互轮次仅作辅助参考（轮次高既可能是引导到位，也可能是引导失效，需抽样人工判读）。
- 效果（核心度量）：讲解后同考点变式题首次做对率 ≥ 50%；教练盲评抽样讲解会话的引导质量，均分 ≥ 3.5 / 5；"听懂了"标记率仅作辅助信号。
- 效果（长期）：错题重练正确率较首次作答有可见提升；考后自评成绩达到所报级别线的比例有正向信号。
- 传播与留存：讲解页存在自然分享；考后愿意继续使用备战 2027 年 3 月考期的比例 ≥ 40%。

反向信号（停止 / 转向条件）：考后变式题做对率或教练盲评均分显著低于目标，或活跃用户远低于目标，则回炉重审 H1 / H6 / H7，必要时调整获客策略或核心价值排序。

## 风险

- R1 **获客张力**：公域内容获客周期长，与 7 周冲刺存在矛盾。缓解：内容围绕"12 月考期冲刺"与"洛谷经典错题错因诊断实录"主题，讲解与诊断案例本身即获客物料；若种子规模不足，降级为邀请制小样本验证，效果结论相应降权。
- R2 **讲解质量**：引导式讲解比直给答案更难做，可能出现误导或超纲；拍照识别的错误会传导至诊断结论。缓解：建立讲解评测集；题目识别结果回显给用户确认后再诊断；题库答案人工校准；上线初期人工抽检。
- R3 **错因诊断技术可行性**：平台不掌握洛谷等 OJ 的测试数据，"边界条件 WA"类错因缺乏数据支撑时诊断准确率存疑。缓解：引导用户同步上传评测结果截图；自建评测机与边界测试数据随 P1 落地后升级为动态重跑验证；测试数据来源见 O7。
- R4 **学生 / 家长价值张力**：引导式是家长与教练视角的价值，学生本人遇挫时更想要答案，可能流向免费直给答案的通用大模型。缓解：阶梯式解锁（卡死可逐级解锁至完整讲解，解锁行为留痕，可生成家长可见的引导过程报告——远期付费点候选）；讲解后以变式题闭环验证是否真懂。
- R5 **题库版权**：GESP 真题的使用授权不明确，存在合规风险。需在 PRD 阶段确认使用政策（见 O2）。
- R6 **未成年人合规**：用户以未成年人为主，涉及个人信息保护与内容安全，即使免费也需合规设计（见 O6）。
- R7 **推理成本**：免费模式下大模型推理成本无收入对冲。需测算单用户成本并设计限额策略（见 O3）。
- R8 **交付压力**：三模块 7 周交付紧张。缓解：已排序 P0/P1/P2，P2 可降级；必要时 P1 仅覆盖首批级别段。
- R9 **考后留存断崖**：12 月考期后至次年 3 月考期间存在天然使用低谷。接受为行业周期特性，考后复盘时再评估。

## 开放问题

- O1：终端形态——微信小程序 vs Web App。公域获客 + 学生触达场景倾向小程序，PRD 阶段决策。
- O2：GESP 真题版权与使用授权政策。
- O3：大模型选型与免费模式下的成本预算上限（P0 要求模型具备图像理解与代码诊断能力，选型范围相应收窄）。
- O4：引导式讲解的质量评测标准——以"讲解后变式题首次做对率 + 教练盲评"为金标准，"听懂标记 / 追问轮次"仅作辅助信号；盲评样本量与评分细则在 PRD 阶段定义。
- O5：2026 年 12 月考期的具体日期与报名截止时间（影响获客内容节奏）。
- O6：未成年人账号体系与数据合规方案（是否需要家长授权机制）。
- O7：GESP 真题测试数据的获取与自命方案（公开渠道收集、按题意构造边界数据、或与数据源合作），直接决定 R3 的缓解上限。
